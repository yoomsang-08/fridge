# 디자인 가이드

냉장고를 부탁해의 화면을 만들 때 따르는 기준입니다. 새 화면이나 기능을 만들 때 이 문서와 `src/components/ui.tsx` 를 먼저 봐 주세요.
시안: 디자인 방향 아티팩트 (프로젝트 공유 폴더 `design/direction.html`)

## 누가, 어떻게 쓰나

- 두 사람(부부)이 주로 **폰 한 손**으로, 냉장고 문을 연 채 빠르게 넣고 확인합니다. PC 와 **아이패드**(주방 거치대·소파에서 두 손)에서도 씁니다.
- 그래서 **입력이 빠르고, 열자마자 뭘 먼저 먹어야 할지 보이는 것**이 가장 중요합니다.

## 원칙 네 가지

1. **색은 경고에만.** 평소엔 무채색, 포인트는 바질 그린 하나. 빨강·주황·겨자는 기한을 챙겨야 하는 식품에만.
2. **엄지로 닿는 곳에.** 주요 동작(탭 메뉴, 식품 넣기, 저장)은 화면 아래.
3. **숫자 대신 말로.** 'D-3' 대신 '3일 남음', 'D+2' 대신 '2일 지남', '오늘까지', '내일까지'.
4. **누를 곳은 크게.** 버튼·칩은 높이 36px 이상(주요 버튼 44px 이상, 태블릿은 44px 이상), 입력 글자는 16px 이상(iOS 확대 방지).

## 색 토큰 (`src/index.css` 의 `@theme`)

Tailwind 클래스로 토큰 이름만 씁니다. `slate-*`, `sky-*`, `red-*` 같은 기본 팔레트나 hex 를 화면 코드에 직접 쓰지 않습니다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `bg` | #f3f5f2 | 앱 배경 |
| `surface` | #ffffff | 카드, 시트, 입력창 |
| `sunken` | #e8ece9 | 보조 버튼, 세그먼트 바탕, 작은 태그 |
| `ink` | #17201c | 본문 글자, 선택된 칩 |
| `muted` | #66726c | 보조 설명, 라벨 |
| `faint` | #9aa59f | placeholder, 꺼진 상태 |
| `line` | #e3e8e4 | 테두리, 구분선 |
| `accent` / `accent-strong` / `accent-soft` | #1e6b52 / #175641 / #e3f1ea | 주요 버튼, 선택 상태, 링크 / 눌림 / 보조 버튼·선택 바탕·포커스 링 |
| `expired` / `expired-soft` | #c8372d / #fbe9e7 | 기한 지남, 삭제·위험 |
| `urgent` / `urgent-soft` | #d2621b / #fdf0e6 | 3일 이내 |
| `soon` / `soon-soft` | #a87a10 / #fbf3dc | 7일 이내 |
| `note-yellow` / `note-pink` / `note-mint` / `note-sky` | #fff1b8 / #fde0e3 / #dcf1e4 / #dceaf6 | 냉장고 문 메모(포스트잇) 종이에만. `src/lib/notes.ts` 의 `notePaper()` 로 고른다 |

- 기한 관련 색은 `src/lib/expiry.ts` 의 `LEVEL_STYLE`(배지: 바탕+글자), `LEVEL_TEXT`(글자만), `LEVEL_DOT`(점), 문구는 `expiryLabel()`, 묶음 이름은 `LEVEL_GROUP` 을 씁니다.
- 경고색(expired/urgent/soon)은 **지금 챙겨야 하는 상태**에만 씁니다: 식품 기한, 냉장고 문이 1분 넘게 열려 있음. 단순 강조나 장식에는 쓰지 않고, 위험 동작(삭제)만 예외로 `expired` 를 씁니다.
- 큰 면을 진한 색으로 채우지 않습니다. 진한 색은 주요 버튼 하나, 나머지는 `*-soft` 바탕 + 진한 글자.

## 글자

- 글꼴: Pretendard (앱에 포함, `font-sans`). 다른 글꼴 추가 금지.
- 단계: 화면 제목 24 extrabold · 시트/섹션 제목 17–18 extrabold · 목록 이름 15 bold · 본문 14–15 · 라벨 13 bold `muted` · 보조 12 `muted` · 아주 작은 태그 10–11.
- 숫자가 줄 맞춰야 하는 곳(수량, 날짜, 개수)은 `tabular` 클래스.
- 집 코드처럼 옮겨 적는 값만 `font-mono` + 넓은 자간.

## 모양

- 둥글기: 카드 `rounded-card`(18px), 버튼·입력 `rounded-2xl`(16px), 작은 버튼·칩 `rounded-xl` / `rounded-full`, 시트 위쪽 28px.
- 그림자: 카드 `shadow-card`(아주 옅게), 떠 있는 '식품 넣기'만 `shadow-float`. 다른 곳에 큰 그림자 금지.
- 간격: 화면 좌우 16px(PC 24px), 카드 안 14–20px, 섹션 사이 12–24px. `gap` 으로 배치하고 요소마다 margin 을 붙이지 않습니다.
- 아이콘: `lucide-react` (선 두께 2 안팎). UI 아이콘에 이모지를 쓰지 않습니다. 식품 **분류**만 이모지 + `categories.ts` 의 `tint` 바탕.

## 화면 패턴

- **탭 메뉴**: `Main.tsx` 의 `TABS` 배열에 추가하면 폰 아래 탭과 PC 머리글에 함께 나옵니다. 탭은 최대 4개. 예외로 **가운데 '식단표'** 한 칸만 동그란 강조 버튼(58px 원, `accent-strong` 바탕 + 흰 아이콘 `Utensils`, 폰은 탭 줄 위로 살짝 솟고 선택되면 `accent` 테두리 링, PC 머리글은 44px 원 아이콘만, 1024px~ 사이드 내비는 44px 원 + 아래 라벨 12px 로 다른 항목과 같은 72×64 칸에 놓음). 이 원만 큰 면을 진한 색으로 채우는 예외이고, 다른 탭은 그대로 무채색입니다.
- **식단표 탭** (`MealPlan.tsx`): 이번 주 + 다음 주 2주치. 폰·태블릿 세로(~1023px)는 맨 위 '목록 / 옆으로 길게' `Segmented`(고른 보기는 이 기기에 기억). '목록'은 '이번 주/다음 주' `Segmented` + 요일 카드, '옆으로 길게'는 두 주 14일을 한 줄로 늘어놓고 좌우로 밀어 보는 표(끼니 이름 열은 왼쪽에 고정, 칸 폭 88px, 열 때 오늘이 왼쪽 끝 가까이)(끼니 행 44px 이상, 비면 '눌러서 적기'), 1024px~ 는 두 주를 요일 7열 × 끼니 행 표로. 칸을 누르면 `Sheet`(끼니 → 메뉴 → '자주 적은 메뉴' 제안 칩 → '냉장고 재료 쓰기' 칩(기한 임박 식품, 기한 문구는 `LEVEL_TEXT` 색, 고르면 먹색 `active` 로 바뀌고 '사용예정' 연결만 바뀜. 메뉴명은 건드리지 않아 식단표에는 적은 메뉴명만 보이고, 메뉴명이 비면 입력칸 아래 `text-xs muted` '먹을 메뉴 이름을 적어 주세요') + '다른 재료 고르기'로 이름 검색). 고른 식품에는 앱 곳곳에 `PlannedChip` 이 붙습니다. 식단을 저장해도 재고 수량은 바뀌지 않습니다. 보이는 끼니(아침·점심·저녁·간식·야식)는 설정 '식단표 끼니'에서 이 기기에 저장. 이 탭에서는 '식품 넣기' 버튼을 숨깁니다.
- **주요 추가 동작**: 오른쪽 아래 '식품 넣기' 버튼 하나. 화면마다 다른 떠 있는 버튼을 더 만들지 않습니다.
- **재고(첫) 화면 맨 위 '오늘 식단표'** (`TodayMeals.tsx`): 오늘 적어 둔 **점심·저녁만** 한 카드 안에 **가로로 나란히**(끼니 이름 13 bold `accent` · 메뉴 17 extrabold, 둘 사이 `line` 세로선). 하나만 적혀 있으면 그 하나만 전체 폭으로. 메뉴에 달걀이 있으면 끼니 이름 옆에 반숙 달걀. 둘 다 비면 '오늘 식단표가 작성되지 않았어요' + '눌러서 오늘 뭐 먹을지 적어 보세요' 한 장(카드 전체가 식단표 탭으로 가는 버튼). 어른/아이 메뉴 칩은 `MealLine` 안, 메뉴 줄 아래에 붙인다.
- **그 아래 '지금 챙길 식품'** (`TodayFocus.tsx`): 3일 안에 먹어야 하는 식품을 급한 순 행 목록으로(이름 16 bold · 기한 문장 · 위치 · '다 먹었어요'). 3개까지, 더 있으면 'N개 더 보기'. 기한 지난 것은 그 아래 따로 묶고 '버렸어요'·'확인하기'. 급한 게 없으면 '오늘 급한 식품은 없어요' 한 장만. 기한은 'D-1' 같은 기호 대신 사람이 하는 말로. 아래 목록에서는 위에 나온 식품을 빼고 '그 밖의 식품'으로 보여 줍니다(검색·거르기 중에는 전부). 크게 보여 주던 '제일 급한 하나' 카드는 식단표에 자리를 내주며 없어졌고, '1개 썼어요'는 식품 상세에서 합니다.
- **목록 행**: 왼쪽 분류 타일(44px) · 이름 + 보조 한 줄 · 오른쪽 기한 문구(`LEVEL_TEXT`) · 빠른 동작(`sunken` 작은 버튼). 행 전체를 누르면 상세.
- **입력 시트 순서**: 무엇(이름) → 어디(칸) → 얼마나 → 언제까지 → 메모. 바코드·검색은 '무엇인가요?' 안에.
- **식품 상세 시트**(이미 넣은 식품을 눌렀을 때): 맨 위에 지금 상태 요약(분류 타일 · 이름 · 수량·위치 · 기한) + 바로 하는 일('1개 썼어요'·'다 먹었어요'·'버렸어요'). 그 아래 '정보 고치기' 양식. 기록 지우기는 맨 아래 작은 글자 버튼.
- **기한 연장**(기한이 지난 식품의 상세 시트에서만): 요약 카드와 빠른 버튼 줄 사이에 `expired-soft` 안내 상자. 제목 '유통기한이 2일 지났어요'(소비기한이면 '소비기한이'), 설명 한두 문장, '오늘부터 [1일 더][3일 더][1주 더]' 칩. 칩은 누르면 바로 저장되어 한 번에 끝나야 합니다(며칠 늘릴지 고르는 단계를 더 두지 않음). 설명 톤은 기한 종류에 따라 다릅니다. **유통기한**은 '파는 기한이라 보관을 잘했다면 며칠 더 먹을 수 있어요. 냄새·색·포장을 확인하고 늘려 주세요', **소비기한**은 '지나면 먹지 않는 게 안전해요. 냉동했거나 상태가 괜찮아 더 둘 거라면 늘려 주세요'처럼 더 조심스럽게. 기한이 지난 식품을 탓하는 말은 쓰지 않습니다.
- **'자동' 표시**: 앱이 알아서 채운 값 옆에는 작은 '자동' 표시를 붙이고, 사용자가 직접 바꾸면 사라집니다. 분류 칩 안에서는 선택된 칩(어두운 바탕) 안에 `bg-white/20 text-[10px] font-bold`, 유통기한 날짜 칸에서는 `bg-accent-soft text-accent text-[11px] font-bold` 작은 배지. 이름을 입력하면 분류가 자동으로 골라지고, 틀린 경우에만 사용자가 칩을 눌러 바꿉니다. 배지는 정보일 뿐 경고색을 쓰지 않습니다.
- **칸 고르기**: 칸이 정해져 있으면 '메인 냉장고 · 냉장 선반 1단 / 바꾸기' 한 줄로 접어 두고, 바꾸기를 눌러야 칸 버튼을 펼칩니다. 칸을 고르면 다시 접힙니다.
- **자세히 보기**: 요약 카드를 눌렀을 때 아래 내용을 제자리에서 펼쳐 화면을 밀어내지 않습니다. 시트로 올리고 닫기는 X.
- **빈 상태**: 가운데 `muted` 한두 문장, 다음 행동을 말로 안내.
- **오류**: `expired-soft` 바탕 + `expired` 글자로 무엇이 안 됐는지와 어떻게 하면 되는지.
- **불러오는 중**: 가운데 `muted` '불러오는 중…'.
- **전체 화면 도구**(바코드 카메라, 3D 보기 등): 어두운 바탕이 필요하면 `ink` 를 쓰고, 닫기는 왼쪽 위 `IconButton`, 주요 동작은 아래쪽.

## 태블릿·넓은 화면 (아이패드 세로/가로)

폰 기준은 그대로 두고, **폭만 보고** 넓은 화면을 더합니다. 기기 이름·`userAgent` 로 가르지 않습니다(아이패드 분할 보기·창 크기 조절·PC 창에서도 똑같이 맞아야 해서). Tailwind 기본 구간을 그대로 씁니다.

### 폭 구간

| 구간 | 폭 | 대표 화면 | 구성 |
|---|---|---|---|
| 폰 | ~639px | 아이폰, 아이패드 Slide Over | 지금 그대로. 한 열, 아래 탭, 좌우 16px |
| 태블릿 세로 | 640–1023px (`sm`·`md`) | 아이패드 미니 744 · 10.9″ 820 · 11″ 834 · 12.9″ 1024 미만 세로, 분할 보기 절반 | 한 열 가운데 정렬, 머리글 탭, 좌우 24px |
| 가로·PC | 1024px~ (`lg`) | 아이패드 가로 1133–1366, PC 1280 | 왼쪽 사이드 내비 + 본문, 필요한 화면은 2열 |

- 구간은 **창 폭**이 정합니다. 아이패드를 돌리면 구간이 바뀌고, 돌려도 보던 탭·열린 시트·입력 중인 값은 그대로 이어집니다(다시 불러오지 않기).
- 좌우 여백: 폰 16px, 640px~ 24px, 1024px~ 32px. 섹션 사이 간격은 폰과 같게(12–24px).

### 본문 폭과 열

- **읽는 폭 `max-w-reading` 720px**: 640–1023px 에서 본문 한 열의 최대 폭. 지금의 `max-w-3xl`(768px) 대신 이 값을 씁니다. 글줄이 너무 길어지면 훑기 어려워서, 더 넓은 화면에서도 목록 글은 이 폭을 넘기지 않습니다.
- **넓은 폭 `max-w-wide` 1120px**: 1024px~ 에서 사이드 내비를 뺀 본문 전체의 최대 폭. 그보다 넓으면 양옆을 비우고 가운데 정렬.
- **2열은 1024px~ 에서만.** 세로(~1023px)에서는 한 열을 지킵니다. 세로 아이패드에서 억지로 나누면 두 열 모두 좁아져 폰보다 불편해요.
- **2열이 되는 화면**(왼쪽이 주, 오른쪽이 보조):
  - **재고**: 왼쪽 '오늘 식단표' + '지금 챙길 식품'(`TodayMeals`·`TodayFocus`) 360px 고정 · 오른쪽 '그 밖의 식품' 목록(남은 폭). 왼쪽은 스크롤해도 따라오게(`sticky`).
  - **냉장고**: 아래 '가로 모드의 냉장고' 참고.
  - **메모**: 포스트잇 보드를 남은 폭에 맞춰 열을 늘립니다(폰 2열 → 태블릿 세로 3열 → 가로 4열, 종이 크기는 그대로).
  - **설정**: 한 열 `max-w-reading` 가운데. 2열로 나누지 않습니다.
- 목록 행은 폭이 넓어져도 **늘이지 않고** 행 높이·타일 크기(44px)를 유지합니다. 남는 폭은 이름 칸이 가져가고, 기한 문구는 오른쪽 끝에 붙입니다.
- 시트(`Sheet`)는 640px~ 에서 가운데 모달(`max-w-lg`)을 그대로 씁니다. 가로 모드에서도 오른쪽 패널로 바꾸지 않아요. 같은 동작이 폭마다 달라지면 헷갈립니다.

### 가로 모드의 냉장고 (3D·평면)

- **1024px~**: 냉장고 그림이 왼쪽 주인공, 오른쪽 360px 에 '냉장고 상태'와 선택한 구역의 식품 목록. 구역을 누르면 오른쪽 목록이 바뀝니다(폰처럼 아래로 내려가며 화면을 밀지 않기).
- 그림 영역: 높이는 보이는 화면에서 머리글을 뺀 만큼(`100dvh`)을 넘기지 않고, 폭은 남은 왼쪽 칸. **냉장고의 가로세로 비율은 폰과 같게** 유지하고 늘이지 않습니다. 남는 자리는 비워 둡니다.
- 3D 는 가운데 정렬, 카메라는 폰과 같은 각도. 냉장고 두 대(냉장고 + 냉동고)는 가로가 충분하면 나란히, 부족하면 폰처럼 하나씩 칩으로 전환.
- 닫힌 문 위 메모·사진·명절 가랜드는 그림과 함께 같은 비율로 커집니다. 글자 크기는 따로 키우지 않고 12px 아래로 줄지도 않게.
- **~1023px(세로)**: 폰과 같은 한 열. 그림은 `max-w-reading` 안에서 가운데, 높이는 화면의 60% 안팎.

### 내비게이션: 아래 탭 vs 머리글 탭 vs 사이드 내비

| 폭 | 내비 | 이유 |
|---|---|---|
| ~639px | **아래 탭** (지금 그대로) | 폰 한 손 엄지 |
| 640–1023px | **머리글 탭** (지금의 `sunken` 세그먼트) | 세로 아이패드는 두 손으로 위쪽을 잡고 쓰는 일이 많고, 아래 탭은 화면 폭 가득이라 너무 멀리 퍼짐 |
| 1024px~ | **왼쪽 사이드 내비** (폭 `w-rail` 88px) | 가로에서는 위아래가 짧고 좌우가 넓어서 내비를 옆으로 빼는 게 본문 높이를 아낌. 아이패드 가로는 양 엄지가 좌우 가장자리에 닿음 |

- 사이드 내비 항목: 아이콘 22px 위, 라벨 12px 아래, 항목 하나 **72×64px**(88px 폭 안에서 좌우 8px 띄워 가운데). 선택은 `accent-soft` 바탕 + `accent` 글자, 나머지는 `muted`. 읽지 않은 메모 배지는 지금처럼 아이콘 오른쪽 위. **식단표**는 항목 안에 44px 동그란 강조 버튼(`accent-strong` 바탕 + 흰 `Utensils` 아이콘 20px) + 아래 라벨 12px 로, 선택되면 `accent` 링(`ring-offset-surface`)과 `accent` 굵은 라벨. 다른 항목처럼 `accent-soft` 바탕은 쓰지 않음.
- 사이드 내비는 `bg-surface` + 오른쪽 `line` 한 줄, 위쪽에 `Logo`, 아래쪽에 '설정'을 둡니다(탭 4개 규칙은 그대로, 설정 포함 수는 지금 `TABS` 를 따름).
- 사이드 내비가 생기면 머리글의 탭 세그먼트는 숨깁니다(같은 내비를 두 번 보이지 않기). 로고·제목·집 이름은 머리글에 그대로.
- **'식품 넣기' 버튼**: 어느 폭이든 하나, 본문 영역의 오른쪽 아래. 640px~ 에서는 본문 컨테이너 오른쪽 가장자리에서 24px 안쪽, 1024px~ 에서는 본문 영역(사이드 내비를 뺀 곳) 오른쪽 아래 32px. 사이드 내비 위에 겹치지 않습니다.
- 모든 내비는 `env(safe-area-inset-*)` 를 지킵니다(가로 노치·홈 인디케이터).

### 누름 크기와 손가락

- 아이패드는 손가락이 더 크고 거치대에서 팔을 뻗어 누르므로 **태블릿(640px~)에서 누름 영역은 44px 이상**이 기본입니다(폰의 36px 하한은 작은 칩에만 남김). 주요 버튼 48px 이상, 사이드 내비 항목 64px.
- 누름 영역 사이 간격 **8px 이상**. 칩 줄·빠른 동작 버튼이 붙어 있으면 간격을 먼저 넓히고, 그래도 모자라면 줄바꿈.
- 입력 글자는 어디서나 16px 이상(iOS 확대 방지). 태블릿에서도 키우지 않습니다.
- **마우스 전용 동작 금지**: 오른쪽 클릭, 가리키면 나타나는 버튼(`hover`) 에만 기대는 기능은 두지 않습니다. hover 는 보조 효과로만 쓰고, 눌림(`active:`) 반응을 기본으로 합니다.
- 가로 모드에서 키보드가 올라와도 입력창과 저장 버튼이 가려지지 않게 시트는 `max-h-[92dvh]` 안에서 스크롤.
- 두 손 동작(핀치 확대 등)은 3D 냉장고 돌리기·확대에만 쓰고, 다른 곳에서는 한 손가락 탭·스크롤로 끝나게.

### 확인 방법 (태블릿 캡처)

PR 설명에 폰(390px)·PC(1280px) 캡처와 함께, 화면 구성이 바뀌는 PR 이면 **세로 820×1180**, **가로 1180×820** 캡처를 붙여 주세요. Playwright `devices['iPad (gen 7)']` 또는 viewport 직접 지정. 구간 경계(639/640, 1023/1024px)에서 레이아웃이 깨지지 않는지도 한 번씩 봅니다.

## 보관 공간 (냉장고 여러 대 + 팬트리)

냉장고 두 대와 실온 팬트리를 모두 '보관 공간'으로 다룹니다. 화면 말로는 '냉장고'를 '보관 공간'으로 넓히지 말고, 각 공간의 이름을 그대로 보여 줍니다.

- **공간 고르기**: 공간이 셋 이상이 될 수 있으니 `Segmented` 대신 가로로 넘기는 `Chip` 줄을 씁니다. 재고 탭의 냉장고 칩과 같은 모양이고, 칩 앞에 16px lucide 아이콘을 붙입니다. 냉장고는 `Refrigerator`, 팬트리는 `Archive`. 순서는 냉장고들(설정 순서) → 팬트리. '3D / 평면' 전환은 칩 줄과 다른 줄 오른쪽에 둡니다.
- **냉장고 문**: 3D·2D 모두 처음에는 **닫힌 문**으로 보여 문 앞 메모가 보이게 합니다. 문을 누르거나 '문 열기' 버튼으로 열고, 다른 탭에 다녀오면 다시 닫힌 상태. 화면 속 문을 연 상태에는 경고색을 쓰지 않습니다. 경고색은 스마트싱스가 알려 주는 진짜 문 열림(1분 넘게)에만.
- **팬트리 모양**: 문 없는 오픈 선반장이라 '문 열기'를 숨깁니다. 3D 재질은 밝은 원목(몸체 `#e6d7bf`, 선반 앞면 `#d6c2a2`, 바구니 `#dcd5c9`)으로, 차가운 흰색 냉장고와 한눈에 구분되게 합니다. 이 색들은 3D 본체에만 쓰고, 2D와 화면 부품은 지금처럼 `sunken`·`line` 무채색.
- **칸 구분 말**: 칸 종류 칩(`ZONE_LABEL`)에 '실온'을 더하고 다른 칸 종류와 같은 `sunken` 칩을 씁니다. 실온이라고 따로 색을 주지 않습니다.
- **식품 넣기 '어디에 넣나요?'**: 공간별로 작은 제목(`text-xs font-bold text-muted`) 아래 칸 버튼을 묶습니다. 공간이 하나뿐이면 제목은 생략.
- **목록 보조 줄**: 공간이 둘 이상이면 '공간 이름 · 칸 이름'(예: '팬트리 · 바구니').
- **설정**: '우리 집 냉장고' 카드 제목을 '보관 공간'으로, 추가 목록에 '팬트리(실온 선반)'를 넣습니다.

### 냉장고 칸은 세 구역만

사용자 요청: 칸 구분이 너무 세부적이라 **냉장 · 냉동 · 김치냉장** 세 구역으로 줄입니다(팬트리는 '실온' 한 구역).

- **데이터와 화면 말**: 칸(데이터)은 구역 하나씩. 목록·시트에는 '냉장실', '냉동실', '김치냉장실'처럼 구역 이름만 나옵니다('선반 1단' 같은 세부 위치 말은 쓰지 않음). `ZONE_LABEL` 은 냉장·냉동·김치냉장·실온.
- **그림(3D·평면)**: 실제 냉장고 모양(선반·서랍·문 포켓 자리)은 그대로 두고, 구역 안 식품을 그 자리들에 고르게 나눠 그립니다. 병·팩·캔은 문 포켓부터. 3D의 세부 위치는 임의여도 됩니다. 빈 자리가 조금 남아도 어색하지 않게(진짜 냉장고도 빈칸이 있음).
- **구역 누르기**: 칸을 누르면 그 구역 전체가 하이라이트되고, 목록·카메라 다가가기도 구역 단위로 동작.
- **평면 이름표**: 구역의 첫 자리에만 작은 이름표(냉장실·냉동실·김치냉장실). 문 포켓에도 구역을 알 수 있게 하는 건 선택 사항(검수 때 '필수 아님'으로 열어 둔 것).

## 문구

- 존댓말, 짧게. '~해요' 체. 버튼은 하는 일을 그대로: '저장', '식품 넣기', '다 먹었어요'.
- 라벨은 질문형: '무엇인가요?', '어디에 넣나요?', '얼마나?', '언제까지?'.
- 개발 용어(API, 동기화 실패 코드 등)를 화면에 그대로 내보내지 않습니다.

## 이스터에그 (써니사이드업 팀 → 송지선 님께)

우리 팀(써니사이드업)은 지선 님이 쓰면서 피식 웃을 작은 장난을 가끔 숨겨 둡니다. 기준은 이렇습니다.

- **찾았을 때만 보이게.** 로고 연타, 특정 단어 입력, 특별한 날짜처럼 일부러 해야 나타나게. 평소 화면과 동작은 그대로.
- **기능을 가리지 않게.** 버튼·입력·기한 경고를 덮거나 늦추지 않습니다. 화면 위에 뜨는 문구·효과는 3초 안에 저절로 사라지고, 누르거나 저장하는 흐름을 막지 않기. 원래 있던 작은 장식을 같은 크기로 바꾸는 것(예: 메모 자석 모양)은 계속 보여도 괜찮아요.
- **색은 토큰 안에서.** 일러스트(예: 반숙 달걀 노른자)만 예외로 작은 면적에 고유 색을 쓸 수 있어요. 큰 화면 전체를 바꾸는 효과, 소리, 자동 재생 금지.
- **움직임은 짧게.** 400ms 이하, `prefers-reduced-motion` 이면 정지 화면으로.
- **말투는 다정하게.** 놀리거나 비꼬는 문구, 기한이 지난 식품을 탓하는 문구는 넣지 않습니다.
- **날의 성격에 맞는 톤.** 축하하는 날(생일·명절·기념일)은 가랜드와 장식으로 즐겁게. **국경일**(삼일절·광복절·개천절·한글날)은 가랜드나 '축하' 문구 없이 머리글 아래 '오늘은 광복절이에요' 같은 **담담한 회색 한 줄**과 메모 자석의 작은 태극기만. **추모하는 날(현충일 등)은 아무 장식도 넣지 않습니다.** 태극기는 위 네 날에만. 새 날을 더할 때는 '축하해도 되는 날인가?'를 먼저 묻습니다.
- **명절 장식 기준.** 장식 그림은 24px 안팎 한 세트처럼 통일하고 토큰 색만 씁니다(`festive-blue` 는 국경일 장식에만, 그 밖에는 `note-*`·`accent`·`urgent` 등). 문구는 머리글 아래 3초 토스트 또는 한 줄, 누름을 통과(`pointer-events-none`).
- **화면 전체를 왜곡하지 않기.** 글자를 늘리거나 흔들거나 기울이는 등 화면 전체 효과는 금지. 캡처할 때 여러 장을 붙여 만든 이미지가 늘어나 보일 수 있으니 원본을 확인합니다.

### 검수하는 사람 (디자인 실장) 가이드

- **역할**: 문서(이 파일)의 주인. 다른 스레드 PR 의 화면·문구·이스터에그를 검수하고, 직접 고치는 건 디자인 쪽(`ui.tsx`, 이 문서, 첫 화면 같은 화면 구성)만. 다른 스레드가 만든 파일은 건드리지 않고 의견을 보냅니다.
- **말투**: 한국어, 밝고 통통 튀는 말투에 디자인은 칼같이. 마지막에 🍳. 사용자 송지선 님은 가장 중요한 사용자(VVIP)라 쉬운 말로, 유민상 님은 개발을 맡은 남편.
- **검수 순서**: ① 폰·PC 캡처가 있는지 → ② 토큰·부품(ui.tsx)을 쓰는지, 기본 팔레트·hex 직접 사용이 없는지 → ③ 경고색이 '지금 챙길 것'에만 쓰였는지 → ④ 누름 영역 36px·입력 16px → ⑤ 문구가 '~해요' 체이고 개발 용어가 없는지 → ⑥ 이스터에그가 위 기준(찾아야 보임, 3초, 400ms, 기능을 가리지 않음, 톤)에 맞는지 → ⑦ 이 문서에 줄이 추가됐는지.
- **결과 전달**: 필수 수정과 선택 사항을 나눠 알려 주고, 필수가 없으면 '디자인 통과, 머지해 주세요'. 수정이 필요하면 어느 캡처의 어디인지 구체적으로.
- **캡처 방법**: `npx vite build && npx vite preview --port 4179`, Playwright `devices['iPhone 13']` 과 1280px PC. 체험 모드에서 '삼성 비스포크 + 쿠쿠 냉동고 등록'을 누르고, localStorage `fridge-demo-v1` 의 `items` 에 식품을 넣어 확인.
- **자동 진행**: 사용자가 '진행 → 점검 → 머지까지 자동으로'라고 했으니, 디자인 쪽 PR 은 점검(`npx tsc -b`, `npx vite build`, `npm run lint`) 후 바로 머지해도 됩니다. 다른 스레드 PR 은 머지를 그 스레드에 맡깁니다.
